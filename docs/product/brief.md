# Продуктовый бриф — it-jobs-finder-bot, итерации I-1–I-2

Источник требований: `docs/plan.md` (§2 объём, §3 критерии, §5 решения чата) +
решение владельца 27.10 по итерации I-2 (весь диалог — на инлайн-кнопках, там где
выбор из списка; §3, §6.1 «Диалог на инлайн-кнопках», AC-21..AC-24).
Настоящий документ уточняет критерии до наблюдаемых/проверяемых и фиксирует точные
форматы вывода бота — на них опираются acceptance-тесты и Gherkin-сценарии.

## 1. Цель продукта

Telegram-бот регулярной IT-подборки: автоматически собирает вакансии с hh.ru и
Habr Career в PostgreSQL и присылает пользователю релевантный дайджест раз в сутки
в выбранное им время (с учётом таймзоны), без необходимости заходить на сайты и
настраивать поиск вручную.

Ценность для пользователя: «открыл Telegram утром — увидел 10 подходящих вакансий,
а не 200 случайных».

## 2. Аудитория

- IT-специалисты в поиске работы или «пассивные кандидаты», следящие за рынком.
- География: СНГ/русскоязычные (основной язык RU), часть — EN.
- Поведение: проверяют Telegram ежедневно; не хотят настраивать сложные фильтры —
  хотят выбрать роль-пресет и при необходимости 2–3 правки.

## 3. Ключевой пользовательский сценарий

1. `/start` → приветствие + выбор языка кнопками («Русский»/«English») → пресеты
   ролей: мультивыбор переключаемыми кнопками (у выбранных — отметка ✅) и кнопка
   «Готово» (7 стартовых пресетов; подписка сохраняется только по «Готово») →
   формат работы кнопками (Удалёнка/Гибрид/Офис/Не важно) → таймзона кнопками
   (города из списка ~30 постранично или «Указать UTC offset вручную» → текстом) →
   время дайджеста текстом (ЧЧ:ММ) → размер дайджеста кнопками (5/10/20/50).
   Текстом остаются только: время HH:MM, мин. зарплата, стоп-слова и ручной UTC-offset;
   прежний текстовый ввод «lang:ru» и slug-пресета текстом упразднены (I-2).
2. Бот раз в час собирает вакансии с обоих источников в общий кэш БД (дедуплицируя).
3. В выбранное время (таймзона пользователя, честный DST) пользователь получает
   дайджест: топ-N ещё не доставленных ему вакансий по подпискам + правкам,
   отсортированных по скорингу релевантности.
4. Пользователь смотрит карточки (заголовок, компания, зарплата, ссылка, возраст,
   источник), переходит по ссылкам, при желании оставляет обратную связь командами
   `/like <n>`, `/dislike <n>`, `/bookmark <n>` (n — номер карточки из последнего
   дайджеста; только статистика для админа, на выдачу не влияет; кнопок в дайджесте
   нет — Q1 остаётся в силе).
5. `/settings` — смена пресетов, правок, размера дайджеста, времени/таймзоны, языка;
   выбор значения — теми же кнопками, что и в онбординге (кроме текстовых шагов).

## 4. Scope

### 4.1 Внутри I-1 (согласовано plan §2)

Источники hh.ru + Habr Career (HTML-парсинг, сбор раз в час), антибот-гигиена
(User-Agent-ротация, джиттер, ретраи с бэкоффом, таймауты, алерт админу при
блоке/капче/пустом разборе), 7 пресетов ролей (JSONB-фильтр + сид-миграция +
админ-CRUD), подписка на несколько пресетов + тонкие правки поверх, дайджест
(сообщение-список, разбивка ≤4096, карточка с возрастом/источником; обратная
связь — команды `/like`, `/dislike`, `/bookmark`), расписание пользователя
(время + таймзона, zoneinfo, догоняющее окно 3 ч),
дедупликация между источниками, RU/EN, открытая регистрация + антиспам,
админ-контур (CRUD пресетов, статистика, ручной сбор, здоровье парсеров),
retention 30 дней (крон 04:15 UTC), очередь рассылки с троттлингом под лимиты
Telegram, graceful degradation (источник упал → дайджест из остальных + алерт),
Docker Compose (bot + db) + Alembic-миграции при старте.

### 4.2 Вне I-1

Чтение Telegram-каналов (отложено решением владельца), прокси-пул, headless-браузер,
антикапча, веб-админка, статусы откликов/мини-CRM, влияние 👍/👎 на выдачу, полный
кастомный фильтр с нуля, моментальные уведомления о новых вакансиях, несколько
времён дайджеста в сутки, приглашения/закрытая регистрация, push в другие мессенджеры.

### 4.3 Внутри I-2 (решение владельца 27.10 — UX)

Перевод всего диалога на инлайн-кнопки там, где выбор из списка:

- `/start`: выбор языка кнопками («Русский»/«English»);
- пресеты ролей: мультивыбор переключаемыми кнопками (отметка ✅ у выбранных) +
  кнопка «Готово»;
- формат работы: кнопки (Удалёнка/Гибрид/Офис/Не важно);
- таймзона: кнопки-города (список из 30, §6.1; постранично) + «Указать UTC offset
  вручную» (далее текстом);
- размер дайджеста: кнопки (5/10/20/50);
- текстом остаются: время HH:MM, мин. зарплата, стоп-слова, ручной UTC-offset;
- каждый callback немедленно подтверждается (`answer_callback_query`); устаревшие/
  чужие кнопки → вежливый отказ, не краш; `callback_data` структурированная,
  валидируемая, ≤64 байт; метки/значения экранируются (`esc`) при выводе;
- Q1 остаётся в силе: в дайджесте кнопок нет (обратная связь — командами).

## 5. Приоритеты

Релиз «всё сразу» (plan §2), поэтому приоритеты — порядок сборки и допустимые
упрощения под давлением (без урезания критерий приёмки §6):

- **P0 (ядро, без него продукт не работает):** сбор + нормализация + дедупликация,
  пресеты + фильтры + правки пользователя, дайджест + расписание + догоняющее окно,
  retention, экранирование HTML (доставляемость сообщений).
- **P1 (обязательно в I-1):** алерты админу, команды обратной связи
  (`/like`, `/dislike`, `/bookmark`) + статистика, i18n RU/EN,
  троттлинг рассылки + graceful degradation, антиспам, админ-CRUD пресетов.
- **P2 (обязательно в I-1, допустимо минимальное упрощение реализации):**
  здоровье парсеров и ручной запуск сбора в /admin (допустим простой статус без
  истории), статистика кликов (допустимы агрегаты-счётчики без разбивки по ролям).

Может ждать следующих итераций: всё из §4.2.

## 6. Критерии приёмки (наблюдаемые и проверяемые)

### 6.1 Точные форматы вывода бота (шаблоны)

Шаблоны — источник истины для acceptance-тестов; любое изменение фиксируется здесь.

**Карточка вакансии (RU и EN, различаются только полями `{salary}`/`{age}`):**

```
{n}. <b>{title}</b>
{company} · {source} · {age}
{salary}
{url}
```

- `{n}` — сквозной номер в дайджесте, с 1; `{title}`, `{company}` — экранированы
  (`app.textutil.esc`); `{url}` — канонический URL (ASCII, не экранируется).
- `{source}` ∈ {`hh.ru`, `Habr Career`}; `{age}` RU: `сегодня` | `вчера` | `{k} дн.`;
  EN: `today` | `yesterday` | `1 day` | `{k} days`; `k` — целое число полных дней
  от `published_at` до момента сбора дайджеста.
- `{salary}` RU: `от {min} {cur}` | `до {max} {cur}` | `{min} – {max} {cur}` |
  `Зарплата не указана`; EN: `from {min} {cur}` | `up to {max} {cur}` |
  `{min} – {max} {cur}` | `Salary not specified`.
  `{cur}`: `₽` | `$` | `€` (RUB/USD/EUR), иначе ISO-код валюты. Число — целое,
  разряды разделены обычным пробелом (U+0020), диапазон через ` – ` (пробел,
  U+2013, пробел).

**Сообщение дайджеста (первая часть):**

```
🔥 Подборка вакансий — {dd}.{mm}.{yyyy} ({count})

{card 1}

{card 2}
...
```

- EN: `🔥 Job digest — {dd}.{mm}.{yyyy} ({count})`.
- `{count}` — число вакансий во всём дайджесте (не в части); карточки разделяются
  одной пустой строкой; части 2+ продолжают список без заголовка со сквозной
  нумерацией.
- Разбивка только по границам карточек; каждая часть — готовый HTML-текст
  длиной ≤ 4096 символов (строгий критерий: считается строка, передаваемая в
  `sendMessage`, включая HTML-теги; это жёстче лимита Telegram и безопасно).
  Если одна карточка не влезает — `{title}` обрезается до 200 символов с `…`
  (остальные поля гарантированно короткие).

**Обратная связь (команды; inline-кнопок в дайджесте нет — решение владельца Q1):**

`/like <n>`, `/dislike <n>`, `/bookmark <n>` — `n` берётся из последнего дайджеста
пользователя; статистика (пользователь, вакансия, действие) пишется, на выдачу
не влияет. Точные строки-ответы:

- Успех RU: `👍 Учтено` | `👎 Учтено` | `🔖 Сохранено`;
  EN: `👍 Noted` | `👎 Noted` | `🔖 Saved`.
- Неверный/отсутствующий `n` RU:
  `Не понял номер. Отправьте номер карточки из последнего дайджеста (например: /like 3).`
  EN: `I didn't get the number. Send the card number from your latest digest (e.g. /like 3).`

**Алерт админу (всегда RU):** `⚠️ Сбор {source}: {reason}`, где `reason` ∈
{`блокировка/капча`, `ошибка разбора разметки`, `пустой разбор`, `источник недоступен`}.
Алерты одного источника — не чаще одного в час (следующие агрегируются).

**Пустой дайджест** (новых/подходящих вакансий нет; решение владельца Q3):

```
🔥 Новых вакансий нет
```

- EN: `🔥 No new vacancies`. Отправляется одним сообщением без карточек.

**Диалог на инлайн-кнопках (I-2; источник истины для acceptance-тестов)**

Общие требования к кнопочному диалогу:

- `callback_data` — структурированная строка `dlg:<step>:<value>`:
  `step` ∈ {`lang`, `preset`, `format`, `tz`, `size`} (+ навигация по страницам
  городов: `dlg:tz:page-<k>`, `k` ≥ 1); `value` — канонический ASCII-код из
  фиксированного набора (`[a-z0-9-]{1,32}`); полная длина строки —
  **≤ 64 байт** (лимит Telegram; самое длинное: `dlg:preset:backend-other` = 22 байта).
  Пользовательский/внешний текст в `callback_data` не попадает никогда — только коды.
- Каждый callback (валидный и невалидный) **немедленно** подтверждается
  `answer_callback_query` — первым действием обработчика, до обращений к БД/сети:
  валидный — пустым текстом (фидбек — обновление сообщения/ответ бота),
  невалидный — toast вежливого отказа (`show_alert=false`). «Часики» не появляются.
- Невалидный callback: неизвестный `step`/`value`, `callback_data` не по грамматике
  или >64 байт, callback не для текущего шага диалога, callback от другого
  пользователя (не владельца диалога) → вежливый отказ (одна строка ниже),
  состояние диалога **не меняется**, исключений/крашей нет.
- Метки кнопок — обычный текст (не HTML); любые значения, выводимые в HTML-текст
  сообщений, проходят `esc` (как и раньше — R7/R53).
- Кнопки есть только в диалоге настроек; **в дайджесте кнопок нет** — Q1 остаётся
  в силе, обратная связь — командами `/like|/dislike|/bookmark` (см. выше).
- Шаги диалога идут в порядке: `lang → preset → format → tz → time → size` →
  «Готово!» (кнопочный выбор открывает следующий шаг сразу; текстовый шаг `time`
  идёт после таймзоны). Каждый завершённый шаг немедленно пишется в профиль;
  подписка на пресеты — только по «Готово» (до этого момента подписка не меняется).
- Прежний текстовый ввод **«lang:ru» упразднён** (как и slug-пресета текстом и
  размер дайджеста текстом): текст на кнопочном шаге не применяется — бот
  переотправляет подсказку шага с клавиатурой (исключение — шаг `tz`, см. §7.12).

Шаги диалога — точные строки (заголовок, кнопки, ответ). Метка выбранного пресета —
префикс `✅ ` перед меткой кнопки.

**Шаг `lang` (выбор языка):**

- Заголовок RU: `Выберите язык:`; EN: `Choose a language:`
- Кнопки (подписи одинаковы в обоих языках): `Русский` = `dlg:lang:ru`;
  `English` = `dlg:lang:en`.
- Приветствие `/start` (язык ещё не выбран, двуязычное):
  `Привет! Я присылаю подборку IT-вакансий.\nHi! I will send you a daily IT jobs digest.\nВыберите язык / Choose your language:`
- Ответ: RU `Язык сохранён.`; EN `Language saved.` → переход к шагу `preset`.

**Шаг `preset` (мультивыбор пресетов):**

- Заголовок RU: `Выберите роли — можно несколько. Выбранные отмечены ✅. Когда закончите, нажмите «Готово».`;
  EN: `Pick roles — you can choose several. Selected roles are marked ✅. Press "Done" when you are finished.`
- Кнопки (метка RU / метка EN = `callback_data`):
  `Python Backend` / `Python Backend` = `dlg:preset:python-backend`;
  `Frontend` / `Frontend` = `dlg:preset:frontend`;
  `DevOps/SRE` / `DevOps/SRE` = `dlg:preset:devops-sre`;
  `Data/ML` / `Data/ML` = `dlg:preset:data-ml`;
  `QA` / `QA` = `dlg:preset:qa`;
  `Mobile` / `Mobile` = `dlg:preset:mobile`;
  `Другие backend-языки` / `Other backend languages` = `dlg:preset:backend-other`;
  `Готово` / `Done` = `dlg:preset:done`.
- Нажатие `dlg:preset:{slug}` переключает отметку (обновляется разметка того же
  сообщения, новый текст не отправляется); подписка пользователя до нажатия
  «Готово» не изменяется.
- `dlg:preset:done` при ≥1 выбранных: RU `Подписка сохранена.`; EN `Subscription saved.`
  → переход к шагу `format`.
- `dlg:preset:done` при 0 выбранных — toast: RU `Выберите хотя бы один пресет.`;
  EN `Pick at least one preset.` (сообщение не меняется, шаг остаётся).

**Шаг `format` (формат работы):**

- Заголовок RU: `Формат работы:`; EN: `Work format:`
- Кнопки: `Удалёнка` / `Remote` = `dlg:format:remote`; `Гибрид` / `Hybrid` = `dlg:format:hybrid`;
  `Офис` / `Office` = `dlg:format:office`; `Не важно` / `Any` = `dlg:format:any`.
- Ответ: RU `Формат работы сохранён.`; EN `Work format saved.`
- В сводке `/settings` формат выводится меткой выбранного значения на языке
  пользователя (`Удалёнка`/`Гибрид`/`Офис`, EN-метки — как выше), `Не важно` → `—`;
  метка проходит `esc`.

**Шаг `time` (время дайджеста) — текстом, строки без изменений:**

- Заголовок RU: `Отправьте время дайджеста в формате ЧЧ:ММ (например: 09:30).`
- Ответ: RU `Время дайджеста сохранено.`; EN `Digest time saved.`
- Ошибка: RU `Не понял время. Отправьте в формате ЧЧ:ММ (например: 09:30).`
  (EN — без изменений).

**Шаг `size` (размер дайджеста):**

- Заголовок RU: `Размер дайджеста:`; EN: `Digest size:`
- Кнопки (метки-числа, одинаковы в обоих языках): `5` = `dlg:size:5`; `10` = `dlg:size:10`;
  `20` = `dlg:size:20`; `50` = `dlg:size:50`.
- Ответ: RU `Размер дайджеста сохранён.`; EN `Digest size saved.`
- Текстовый ввод размера упразднён; строка `error.bad_size` удаляется из словаря.

**Завершение онбординга (без изменений):** RU `Готово! Подборка придёт в выбранное время.`;
EN `All set! Your digest will arrive at the chosen time.`

**Вежливый отказ на невалидный callback (устаревший/чужой/битый):**

- RU: `Эта кнопка устарела. Откройте настройки заново (/settings).`
- EN: `This button is outdated. Open settings again (/settings).`

Передаётся текстом в `answer_callback_query` (toast, `show_alert=false`);
сообщения с клавиатурами не редактируются, состояние диалога не меняется.

**Текстовый ввод (остаётся только это):** время `HH:MM` (шаг `time`), мин. зарплата
(RU `Отправьте минимальную зарплату в рублях (например: 150000).`), стоп-слова
(RU `Отправьте стоп-слово для фильтрации вакансий.`), ручной UTC-offset
(шаг `tz` после `dlg:tz:manual`). Иных текстовых значений в диалоге нет (AC-24).

## 7. Принятые интерпретации (не блокируют работу)

Спорные места, решённые продуктом; владелец может переопределить без потери работы:

1. **Дедупликация и доставка:** канонический URL — первый признак; если URL различаются
   (разные источники) — нормализованные (lowercase, без пунктуации/двойных пробелов)
   заголовок + название компании. Учёт доставки per-user (решение владельца Q2):
   каждая вакансия доставляется пользователю максимум один раз, повторная доставка
   исключается независимо от выпуска (AC-19).
2. **Размер дайджеста:** границы 1..50, дефолт 10; «меньше вакансий — приходит меньше».
3. **Зарплата:** показываем как в источнике (gross/net не разделяем); сравнение с
   «мин. зарплатой» пользователя — приблизительное, по курсам
   `app/domain/currency.py` (ограничение отражено в риске R8).
4. **Правки пользователя** (мин. зарплата, формат работы, стоп-слова) — глобальные
   поверх всех подписанных пресетов (не per-пресет).
5. **Сортировка дайджеста:** по скорингу релевантности (уб.), при равенстве — более
   свежие (`published_at` уб.).
6. **Расписание:** одно время в сутки; время очистки retention (04:15) — UTC.
7. **Пустой дайджест** — отправляем сообщение по шаблону §6.1 (решение владельца
   Q3; AC-20).
8. **Первый дайджест** — в ближайшее выбранное время (не сразу после `/start`).
9. **Таймзона** — список из ~30 городов + ручной UTC-offset.
10. **Алерты админу** — всегда RU; не чаще одного в час на источник.
11. **Кнопочный диалог (I-2):** цепочка онбординга — `lang → preset → format → tz →
    time → size` → «Готово!» (порядок согласован с decisions §8.6; владелец может
    переставить шаги). Те же клавиатуры используются в `/settings <шаг>`.
12. **Текст на кнопочном шаге** (включая старый `lang:ru`) не применяется: бот
    переотправляет подсказку шага с клавиатурой. Исключение: шаг `tz` — текст
    трактуется как ручной UTC-offset и принимается и без нажатия «Указать UTC offset
    вручную» (обратная совместимость и удобство).
13. **Размер дайджеста** — только 5/10/20/50 (решение владельца 27.10, уточняет
    AC-8: прежние «1..50 текстом» упразднены); уже сохранённые значения вне набора
    (например 7) продолжают действовать, но не могут быть выбраны заново.
14. **Формат работы:** канонические значения `remote` | `hybrid` | `office`;
    «Не важно» (`dlg:format:any`) — правка снимается (`null`). В `/settings` выводится
    метка, не сырое значение. Правила сопоставления канонических значений с текстом
    вакансии (ключевые слова RU/EN) фиксирует business-analyst в `docs/spec/`;
    legacy-строки профилей (например «удалённо») продолжают матчиться как раньше
    (обратная совместимость).
15. **Метки пресетов:** RU — имена AC-5; EN — `preset.{slug}` из i18n (для
    админ-пресетов без перевода — `name_ru`); метка всегда проходит `esc` в HTML-тексте.
16. **«Готово» при 0 выбранных пресетах** — вежливый отказ «Выберите хотя бы один
    пресет.»: пустая подписка запрещена (иначе пустые дайджесты — R58/R11).
17. **Меню `/settings`** (кнопки перехода к шагам наравне с `/settings <шаг>`) —
    рекомендуется для I-2, но не обязательно: минимально навигация остаётся
    текстовой командой `/settings <шаг>`. **Вопрос владельцу** (не блокирует).
