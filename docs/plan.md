# План: it-jobs-finder-bot — итерация I-1

Статусы: **[сделано]** / **[в работе]** / **[не начато]**. Факт важнее оценки.

## 1. Цель

Telegram-бот регулярной подборки IT-вакансий: парсит hh.ru и Habr Career (HTML, API hh закрыт с 04.2026),
копит вакансии в PostgreSQL и шлёт дайджест по расписанию, выбранному пользователем, по подписанным
ролям-пресетам с личными правками. Стек: Python 3.12, aiogram 3, SQLAlchemy 2 (async) + asyncpg,
Alembic, APScheduler, PostgreSQL, Docker Compose.

## 2. Объём (согласован в чате, «всё сразу» одним релизом)

1. Источники: парсинг hh.ru и Habr Career; сбор раз в час в общий кэш БД; дайджест из накопленного.
2. Антибот-гигиена: ротация User-Agent, джиттер, ретраи с бэкоффом, таймауты; алерт админу при
   блоке/капче/пустом разборе. Без прокси и headless-браузера.
3. Пресеты ролей (7 стартовых: Python Backend, Frontend, DevOps/SRE, Data/ML, QA, Mobile, другие
   backend-языки): JSONB-фильтр — роль, стек (must/nice), грейд, зарплата, формат работы, локация,
   стоп-слова, тип занятости. Хранение в БД + сид-миграция; правка админом через /admin-команды.
4. Подписка пользователя: несколько пресетов сразу + тонкие правки поверх (мин. зарплата, формат
   работы, стоп-слова). Полный кастомный фильтр с нуля — вне объёма.
5. Дайджест: одно сообщение-список; размер настраиваемый, дефолт 10; >4096 символов — разбивка.
   Карточка: заголовок, компания, зарплата, ссылка + возраст вакансии и источник + кнопки 👍/👎/🔖.
6. Расписание: пользователь выбирает время сам + таймзона (UTC-offset/город из списка). Честная
   обработка DST (zoneinfo).
7. Кнопки обратной связи — только статистика (топ интересного для админа), на выдачу не влияют.
8. Дедупликация: уникальность между источниками (канонический URL или нормализованные
   заголовок+компания).
9. UI: русский/английский с выбором при старте (i18n-словари).
10. Доступ: открытая регистрация + антиспам (лимиты действий, тихий мьют).
11. Админ-контур в боте: CRUD пресетов, статистика (пользователи, клики), ручной запуск сбора,
    здоровье парсеров.
12. Retention: вакансии старше 30 дней чистятся кроном (04:15); время в БД — UTC.
13. Рассылка: очередь с троттлингом под лимиты Telegram API; graceful degradation — источник упал,
    дайджест из остальных + алерт.
14. Инфраструктура: Docker Compose (bot + db) для VPS; миграции Alembic выполняются при старте.

Вне объёма I-1: чтение Telegram-каналов (отложено решением владельца), прокси-пул, headless-браузер,
антикапча, веб-админка, статусы откликов/мини-CRM, влияние 👍/👎 на выдачу.

## 3. Критерии приёмки I-1

1. Чистый прогон: `.venv/bin/python -m pytest` (unit + acceptance + security) зелёный; `tests/e2e`
   зелёный против локального PostgreSQL (`jobs_test`) или явно пропущен при недоступной БД.
2. Коллекторы hh и Habr Career из HTML-фикстур дают нормализованные вакансии; битая разметка →
   `ParseError`; блокировка → `SourceBlocked`; коллекторы не ходят в сеть в тестах (FakeClient).
3. Дедупликация: одна и та же вакансия из двух источников сохраняется один раз.
4. Пресеты: сид-миграция создаёт 7 ролей; подписка на несколько пресетов + правки пользователя
   влияют на отбор.
5. Дайджест: собирается из кэша, содержит карточку (заголовок/компания/зарплата/ссылка/возраст/
   источник), каждая часть ≤4096 символов, разбивка не рвёт карточку; кнопки 👍/👎/🔖 пишут статистику.
6. Расписание: рассылка в выбранное пользователем время с учётом tz-offset; «догоняющее окно» 3 ч;
   очистка вакансий старше 30 дней работает по крону.
7. Безопасность: весь внешний и пользовательский текст экранирован (нет HTML-инъекции в Telegram),
   админ-команды доступны только ADMIN_ID, запросы к БД параметризованы, секреты — только из env;
   security-тесты красные → зелёные, отчёт без открытых high/critical.
8. Инфраструктура: `ruff check .` и `ruff format --check .` чистые; `docker-compose.yml` + `Dockerfile`
   на месте; `alembic upgrade head` работает на чистой БД; `.env.example` покрывает все переменные.

## 4. Ограничения

- Python 3.12; запуск из корня репозитория (`pip install -e .` не работает); тестовая БД обязана
  оканчиваться на `_test`; тесты не ходят в сеть; `asyncio_mode = "auto"`.
- Парсеры обязаны бросать `ParseError`/`SourceBlocked`, не возвращать пустой список молча
  (пустой сбор = алерт админу).
- Весь текст для Telegram — HTML через `app.textutil.esc`/`esc_attr`; допустимые теги фиксирует
  `tests/html_check.py`.
- Модель меняется — в том же цикле добавляется миграция; время в БД — UTC, расписание — таймзона
  пользователя.
- Тесты: схема БД из моделей (`drop_all`/`create_all` на тест); e2e не трогает рабочие БД.
- Окружение: PostgreSQL 14 локально доступен (`jobs_test` создан); docker-демон на машине сейчас
  падает — файлы Docker будут проверены статически, сборка образа в I-1 не подтверждается.
- Заметных дедлайнов нет: сроки не обещаются, фиксируется только факт готовности.

## 5. Решения из чата (решающие для архитектуры)

1. Источники: парсинг (hh API закрыт с 04.2026 — проверено), Habr Career; Telegram-каналы отложены
   (противоречие с черновиком профиля «hh + telegram активны» — принято решение чата, см.
   `docs/spec/decisions.md`).
2. Дайджест по расписанию пользователя (время + tz-offset), не моментальные уведомления.
3. MVP с прицелом на рост: открытая регистрация + антиспам.
4. Пресеты: гибрид — БД + админ-команды; пользователь: несколько пресетов + тонкие правки.
5. Полный набор фильтров пресета (роль, стек, грейд, зарплата, формат, локация, стоп-слова, занятость).
6. Карточка: база + возраст/источник + кнопки; кнопки — статистика; дедуп — между источниками.
7. RU/EN интерфейс с выбором; размер выпуска настраиваемый (дефолт 10); retention 30 дней.
8. Сбор — раз в час; антибот — гигиена + алерты; деплой — Docker Compose на VPS.

## 6. Порядок сборки внутри релиза

Bootstrap → модель данных+миграции+сиды пресетов → парсеры+нормализация+дедуп → кэш/скоринг →
дайджест+рассылка по расписанию → UX пользователя → кнопки/админка/i18n → Docker/крон/антиспам.
